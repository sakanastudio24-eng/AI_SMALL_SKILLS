## Purpose
Guide hosted manual test sheet creation and review across release scope, environment coverage, reproducible test cases, result tracking, and bug follow-up.

## Use When
- creating a shared manual QA sheet
- preparing hosted release checks
- organizing smoke tests for staging or production
- reviewing whether a test sheet is actionable
- tracking manual verification across environments

## Do Not Use When
- building automated test frameworks directly
- reviewing code-level test implementation
- solving product architecture questions unrelated to QA flow

## Inputs Needed
- release scope
- target environment
- critical user journeys
- roles or permission states
- owners or testers
- expected result format

## Steps
1. Define the environment and release surface.
2. Structure the sheet around reproducible test cases.
3. Cover happy path, failure path, auth, and permission states.
4. Record pass, fail, and block outcomes clearly.
5. Link bugs and keep the sheet maintainable over time.

## Output
- test sheet structure
- required fields or columns
- case coverage guidance
- bug follow-up rules
- maintenance notes

## Constraints
- test cases should be reproducible
- expected results should be concrete
- release-critical checks should not be buried in exploratory notes
- blocked or failed results should link to follow-up work
