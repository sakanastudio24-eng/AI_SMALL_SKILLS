# Plan / Implement / Change Checklist

## Request Classification
- [ ] Request mode is identified as plan, implement, review, or revise
- [ ] Existing versus net-new work is clear
- [ ] Success criteria are stated
- [ ] Scope blockers are listed
- [ ] Next step matches the chosen mode

## Planning Gate
- [ ] High-impact product choices are resolved before implementation
- [ ] Important tradeoffs are surfaced explicitly
- [ ] Assumptions are listed if the user did not provide them
- [ ] The plan is specific enough to execute
- [ ] The request is not being over-planned unnecessarily

## Change Request Gate
- [ ] The requested delta from prior work is restated clearly
- [ ] Out-of-scope carryover is excluded
- [ ] Existing behavior that must remain unchanged is noted
- [ ] Review and implementation are separated if needed
- [ ] Follow-up work is scoped intentionally
