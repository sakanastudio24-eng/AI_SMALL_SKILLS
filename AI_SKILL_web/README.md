# AI_SKILL_web

## Purpose
Design and improve web pages and web app surfaces with clear hierarchy, usable flows, and responsive behavior.

## Use When
- designing landing pages
- reviewing dashboard UX
- cleaning up confusing UI flows
- planning frontend implementation
- auditing mobile and desktop behavior

## Do Not Use When
- solving backend-only architecture problems
- designing auth security rules
- doing non-web platform work

## Inputs Needed
- page or screen type
- primary user action
- content or section list
- mobile and desktop expectations
- design system or brand constraints

## Steps
1. Identify the surface type and primary user action.
2. Clarify the content hierarchy and key UI states.
3. Check desktop and mobile behavior.
4. Simplify actions, navigation, and visual weight.
5. Recommend concrete component and layout changes.

## Output
- page or screen improvement plan
- hierarchy and layout guidance
- state handling guidance
- practical UI review checklist

## Constraints
- keep one dominant action per viewport
- define loading, empty, success, and error states
- do not add decorative complexity before fixing hierarchy
- preserve the existing design system when one exists
