## Purpose
Guide React Native mobile workflows across screen planning, navigation, state flow, auth handling, animation decisions, device constraints, testing, and shipping readiness.

## Use When
- planning a mobile feature
- structuring React Native screens
- deciding navigation flow
- handling auth on mobile
- planning animations or transitions
- reviewing device-specific behavior
- adapting web product ideas into mobile workflows

## Do Not Use When
- building website-only features
- solving extension-only runtime issues
- making backend architecture decisions outside mobile scope

## Inputs Needed
- mobile feature goal
- involved screens
- user flow
- navigation pattern
- state dependencies
- auth requirements
- device-specific concerns
- animation or interaction needs

## Steps
1. Define the mobile user flow screen by screen.
2. Identify which navigation pattern fits the feature.
3. Separate screen state, shared state, and backend state.
4. Plan loading, empty, offline, success, and failure states.
5. Review touch behavior, gestures, and transition expectations.
6. Check platform-specific differences between iOS and Android if relevant.
7. Validate the auth flow for mobile session behavior.
8. Confirm the screen is practical on real device sizes.

## Output
- mobile flow plan
- screen breakdown
- navigation recommendation
- state handling guidance
- interaction checklist
- mobile QA notes

## Constraints
- mobile should not be treated like a compressed website
- prioritize clarity and touch usability
- avoid overcomplicated navigation
- animations should support flow, not distract from it
- always account for loading, error, and device-size edge cases
