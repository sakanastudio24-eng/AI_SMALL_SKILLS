# AI_SKILL_web_design_system_workflows

## Purpose
Handle web design system creation, audit, rollout, and adoption across tokens, components, docs, and frontend implementation workflows.

## Use When
- creating a design system
- auditing an inconsistent system
- rolling tokens and components into a codebase
- documenting usage rules
- planning design-system adoption work

## Do Not Use When
- doing isolated page tweaks without system scope
- building unrelated backend logic
- making auth-only implementation decisions

## Inputs Needed
- brand or product context
- current token or styling setup
- target outputs such as tokens, components, docs, or rollout plan
- framework or frontend stack
- multi-theme or multi-brand requirements

## Steps
1. Classify whether the task is new-system, refresh, adoption, or audit.
2. Define foundations before component work.
3. Create or review the token model.
4. Define component and documentation structure.
5. Add rollout or governance guidance.

## Output
- design-system plan
- token and component guidance
- adoption or audit guidance
- implementation checklist

## Constraints
- tokens first, components second
- semantic names beat visual names
- do not rebuild the entire system when a smaller fix solves the problem
- design-system changes require manual review before shipping broadly
